# FitBuddy: AI-Powered Fitness Plan Generator

This repository implements FitBuddy as a runnable FastAPI web application. Enter a few personal details, get a Gemini-written 7-day workout plan and a nutrition tip, then ask for changes in plain words and receive an updated plan.

**Live app:** https://fitbuddy-u8r0.onrender.com/

## What is included

- FastAPI backend
- Jinja2 / HTML / CSS frontend (dark theme with gym background)
- Profile form with Pydantic validation
- 7-day workout plan generated by Google Gemini (`google-genai` SDK)
- Nutrition tip for the chosen goal, with a built-in fallback tip
- Feedback step that returns a complete updated plan (original stays viewable)
- Model fallback chain: tries several Gemini models and remembers the one that worked
- SQLite storage for users and plans (SQLAlchemy)
- Coach view with all users, original and updated plans, and a delete option
- JSON API with Swagger/OpenAPI documentation at `/docs`

## Gemini models

Defaults are set in code and can be changed in `.env`:

| Setting | Default |
| --- | --- |
| `WORKOUT_MODEL` | `gemini-3.6-flash` |
| `TIP_MODEL` | `gemini-3.5-flash-lite` |

If a model is retired or busy, FitBuddy tries the next one in the fallback chain. Change these values if your account provides other supported models.

## VS Code setup

1. Install Python 3.10+.
2. Open this folder in VS Code.
3. Open Terminal.
4. Create and activate a virtual environment.
5. Install requirements.
6. Create a `.env` file and add your Gemini API key (free from [Google AI Studio](https://aistudio.google.com/apikey)).
7. Run `uvicorn app.main:app --reload`.
8. Open http://127.0.0.1:8000.

### Windows

```powershell
py -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### macOS / Linux

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### `.env` file

```env
GOOGLE_API_KEY=your_api_key_here
# Optional
WORKOUT_MODEL=gemini-3.6-flash
TIP_MODEL=gemini-3.5-flash-lite
```

### Run

```bash
uvicorn app.main:app --reload
```

Then visit `/docs` for API testing.

## Typical test flow

1. Open the home page and submit: name Anu, user ID 1, age 18, weight 50, goal Weight loss, intensity High.
2. Check the 7-day plan and the nutrition tip.
3. In "Change your plan", enter user ID 1 and feedback "Add more rest days please".
4. Verify the updated plan and open "View your original plan".
5. Open the Coach view (`/view-all-users`) and verify both plans are listed.
6. Delete the user and confirm the row disappears.

## Input rules

| Field | Rule |
| --- | --- |
| user_id | Whole number greater than 0 |
| username | 1 to 60 characters |
| age | 10 to 100 |
| weight | Above 20 and up to 400 kg |
| goal | 2 to 200 characters |
| intensity | low, medium or high |
| feedback | 3 to 500 characters |

## Routes

| Method | Route | Description |
| --- | --- | --- |
| GET | `/` | Home page with the profile form |
| POST | `/generate-workout` | Generates plan and tip, saves them |
| POST | `/submit-feedback` | Updates the plan from feedback |
| GET | `/view-all-users` | Coach view |
| POST | `/delete-user/{user_id}` | Deletes a user and plan |
| POST | `/generate-plan` | JSON: generate and save a plan |
| POST | `/generate-workout/gemini` | JSON: plan without saving |
| GET | `/nutrition-tip?goal=` | JSON: nutrition tip |
| POST | `/update-plan/{user_id}` | JSON: updated plan (404 if no plan) |
| GET | `/docs` | Swagger UI |

## Architecture

Browser → FastAPI routes → Pydantic validation → Gemini (with model fallback) → SQLite → browser.

```
app/
├── main.py                    # app + lifespan, creates tables
├── routes.py                  # pages + JSON API
├── schemas.py                 # Pydantic models
├── database.py                # models + helpers
├── gemini_generator.py        # client, fallback chain, workout plan
├── gemini_flash_generator.py  # nutrition tip
├── updated_plan.py            # plan revision
├── nutrition.py               # fallback tips
├── templates/                 # index, result, all_users
└── static/images/             # gym-bg.jpg
```

## Deployment (Render)

1. Push the code to GitHub without `.env`.
2. Create a Web Service and connect the repository.
3. Build command: `pip install -r requirements.txt`
4. Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. Add `GOOGLE_API_KEY` (and optionally `WORKOUT_MODEL`, `TIP_MODEL`) as environment variables.

## Production notes

- Keep `.env`, `venv/` and `fitbuddy.db` out of Git.
- Do not expose `GOOGLE_API_KEY` to the frontend.
- Add login before storing real user data. The coach view and delete button are currently open.
- Use a production database such as PostgreSQL. SQLite may reset on free hosting.
- Add rate limiting, structured logging and HTTPS.
- Add an automated pytest suite with a mock Gemini client (testing is manual for now).
